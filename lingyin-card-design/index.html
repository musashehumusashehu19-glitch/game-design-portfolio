01 · PROJECT BRIEF

任务不是救强度，而是补内容、补选择，并把方案真正做进游戏。

7月9日，导师提出“尝试设计凌音后续卡牌，不仅要设计，还要落地配置”。月底前完成方案和本地验证是当时的主要交付预期。

上线背景

英雄有热度、强度也不低，但专属卡牌内容仍停留在基础版。

  • 凌音上线约半年，在自制新英雄中热度表现较好。
  • 初始强度一般；1技能治疗在约一个月前加强后，已成为辅助 T0。
  • 已有卡牌大多是随英雄上线的基础卡，没有形成清晰 Build。
  • 主流玩法集中于用大招进行范围强控，其他技能和被动缺少进一步塑造。
任务目标

以“接近新英雄内容更新”的体感，补齐卡池并增加玩法多样性。

  • 补齐完整卡池：3张通用数值卡 + 21张英雄专属卡。
  • 建立可识别的玩法方向，让卡牌之间产生化学反应。
  • 卡牌表现要有吸引力，但强势英雄不能再获得无条件增益。
  • 交付方案、数值表、配置表与本地测试结果，上线前再进入内部跑测。
个人起点

具备进入落地阶段的基础。

实习约半年，已做过多项平衡性方案；熟悉项目配置流程、UE4技能时间轴和基础数值工作，希望把数值与战斗设计能力整合成可交付成果。

边界条件

资源与程序边界并未完全明确。

卡牌数量和品质结构明确，但美术、程序与复杂机制成本没有预先给出详细清单，因此方案需要在沟通过程中不断做可行性收敛。

完成定义

先以本地测试通过作为阶段终点。

当前阶段主要由本人完成方案、数值与简单配置；复杂效果尚未进入程序对接。阶段性完成标准是本地训练场中触发、筛选和数值表现正确。

02 · SYSTEM CONSTRAINTS

随机选卡决定了 Build 只能是“软组合”，不能是必须凑齐的套装。

这条系统规则直接改变设计方法：单卡必须独立成立，同 Build 卡牌围绕共同战斗目标形成增量联动，而不能互相充当前置条件。

PRESET局前预选

每轮预选3张同品质卡牌进入候选。

RANDOM OFFER局内二选一

系统从预选内容中随机展示2张供玩家选择。

QUALITY LIMIT最多蓝紫橙各1张

一局最多拿到3张英雄专属卡，不保证形成完整 Build。

DESIGN RESULT单卡可用，组合增益

完整组合是奖励，不是卡牌正常工作的前提。

本项目对 Build 的定义

三张卡作用于同一个战斗目标，形成清晰玩法循环；每张卡独立使用仍有效，同 Build 内存在联动，但没有强依赖、互斥冲突或“没抽到核心卡就失效”的问题。

品质 ≠ 固定职能

蓝紫橙对应递增的整局价值预算。

公开版以1∶1.5∶2的相对梯度表达。品质不预设“启动—放大—质变”分工，效果是否匹配品质，主要由价值预算、Build完整性与数据表现共同判断。

形成概率

没有单独建立抽取概率模型。

项目中没有明确要求计算Build成型概率，因此采用经验约束：降低组合内强依赖，保证每张卡可单独工作，并避免同品质或同机制冲突。

强度原则

理论值允许围绕标准上下浮动。

卡牌可以略低或略高于品质预算；实际强度还会受历史调整、机制价值和实战环境影响，最终仍需以测试与数据校准。

03 · HERO KIT

先理解凌音原本的战斗循环，才能判断卡牌该放大什么、改造什么。

凌音是辅助／控制英雄。她通过技能命中和“完美时刻”积攒音量，满100进入热舞模式；现有实战价值高度集中在大招控制。

PASSIVE

震撼音域

附近友方提升移速和攻速，敌方降低移速和攻速。命中目标与触发完美时刻会收集音量；音量集满后进入热舞模式，提升自身移速与被动效果，期间持续消耗音量。

卡牌机会：音量循环、热舞覆盖、强化普攻与团队增益。
SKILL 01

即兴表演

放下音箱，在范围内伤害并减速敌方、提高其承伤；范围内友军每秒回复生命。原技能以静态范围持续生效。

卡牌机会：让音箱追随敌人进行干扰，或吸附队友强化辅助。
SKILL 02

动感滑步

向前滑行并留下为队友加速的路径，自身获得可击飞敌人的强化普攻；二段滑行拥有完美时刻判定，成功后提高强普伤害并获取更多音量。

卡牌机会：增加段数与操作频率，或把功能位移改造成进攻手段。
ULTIMATE

舞力全开

放下音箱并迫使范围内敌人起舞；期间可再次释放最多三道音浪，每段都有完美时刻判定。原本落地移动会取消大招。

卡牌机会：允许受限移动、延长表演窗口，同时保留打断反制。
04 · ITERATION

方案不是一次想对，而是在反馈中从“数值增强”走向“玩法重构”。

时间顺序：V1三套Build → V2蹦蹦床探索 → V3共同粗拆六路 → V4补全六路 → 当前版数值与效果收敛。

V17月中旬

增益流 / 滑步流 / 大招团控流

增益流散布在各技能，像一组散卡；大招流只是增加持续时间，表现偏保守；三套方案都过度强调“完美时刻”，熟练玩家收益有限。

滑步流最完整：增加滑行段数，路径留下类似《英雄联盟》派克E的延迟残影，橙卡参考洛大招的穿行控制。导师也认为滑步方向相对成立。

V2高表现探索

1技能“蹦蹦床流”

1技能圈持续6秒。获得核心卡后，只要凌音与敌人同时在圈内，使用游戏独有的跳跃键（最多储存4次）便让敌人同步被击飞；完整组合还允许圈外队友接近被影响目标。

导师评价“脑洞很大”，同时指出实现难度较高，但没有否定方向。它证明方案需要更强表现力，也暴露了前期缺少机制可行性评估的问题；后续改用更稳健的六路结构。

V37月22—23日

按技能目标粗拆六路

在有经验同事指出“被动流过多、技能覆盖不足、三张新卡Build感弱、部分效果难实现”后，共同提出按技能拆不同方向。两条1技能方向由同事提出，其余方向由本人提出。

“大招变移动式范围控制”是好方向，但必须保留克制。由此形成受限移速移动、仍可被打断的巡回舞台，而不是无条件范围硬控。

V4补全方案

完成蓝紫橙组合与卡位排布

在六路框架上补齐每张卡的具体机制、品质、循环和卡位关系；避免同品质冲突，保证共享卡“三连拍”可以服务两个2技能方向。

导师与同事认为整体方向可行，方案从讨论阶段进入数值计算和本地制作。最能代表个人独立设计的是三连拍、完美律动、巡回舞台。

NOW当前版

与数值同事讨论后收敛

把百分比生命伤害改为法强成长伤害，降低打坦风险；调整完美律动收益；聚光灯改为拖拽吸附并强化保护；终曲乐章确定减速上限与低生命斩杀阈值。

大部分效果和数值已确定，开始配置。追拍因吸引力不足、高频音障因保护射手与近战进攻诉求冲突，仍需重新设计。

贡献口径：导师负责目标与关键反馈；有经验同事参与六路框架讨论并提出两条1技能方向；数值同事参与当前版效果和数值收敛；本人负责资料研究、核心机制补全、整体方案、数值预算、简单配置与本地验证。

05 · BUILD SYSTEM

六条方向覆盖被动与三个主动技能，每条都有共同战斗目标。

Build用于组织设计和传达玩法，不承诺一局必然凑齐。单卡可用、组合有循环，是贯穿六路方案的统一原则。

01
PASSIVE

被动流

更快积攒音量，放大热舞状态下的个人进攻和团队辅助收益。

蓄能→协奏混响→洗脑节拍
循环：更快积攒音量 → 更早进入热舞 → 热舞期间强化自身与队友 → 更充分利用洗脑节拍。
02
SKILL 01

干扰敌方

让静态音箱具备追踪与施压能力，同时强化凌音的伤害方向。

扩音器→音响炸弹→终曲乐章
连锁：扩大范围 → 自动跟随 → 爆炸击飞 → 持续减速与增伤 → 低血量斩杀。
03
SKILL 01

增益友方

把音箱圈吸附到队友身上，支持多目标布置、增幅和保护。

安可→聚光灯→高频音障（待改）
循环：增加存储 → 为多个队友放置 → 圈跟随队友 → 提供治疗、减伤与技能免疫。
04
SKILL 02

频率流

奖励连续滑步与成功判定，围绕操作频率和热舞状态形成正循环。

炫技→三连拍→完美律动
循环：更多滑行段数 → 更多完美判定 → 获得音量、免伤和冷却收益 → 更快进入热舞。
05
SKILL 02

进攻流

把原本偏功能性的位移路径转化为可控方向的主动输出手段。

重步音冲→三连拍→回响共振
循环：扩大路径并增加法强成长碰撞伤害 → 追加一段滑步 → 幻象延迟复制2技能。
06
ULTIMATE

大招移动流

将定点强控改造成可以追随战场的表演，同时通过低移速和可打断保留反制。

延时演出→巡回舞台→舞乐领域
循环：延长判定窗口 → 以受限移速移动并缩短剩余冷却 → 扩大范围与伤害；落地移动仍可取消。
INDEPENDENT DESIGN 01

三连拍

2技能原本仅有两段滑行和一次完美时刻。三连拍增加第三段滑行与判定，成功后自动在地面释放强化普攻；滑行方向仍由玩家控制，不额外增加方向选择或时间窗口。

  • 强化了最初滑步流的操作表现
  • 同时服务频率流与进攻流
  • 单卡增加操作上限，组合后放大循环
INDEPENDENT DESIGN 02

完美律动

把熟练操作的收益从单纯“判定成功”扩展为音量、免伤与2技能冷却收益。目标是让一套成功技能判定配合技能本身的音量获取，能够进入热舞模式。

  • 仍要求原有判定成功，不把操作自动化
  • 不触发时卡牌基础效果仍然存在
  • 数值计算按熟练玩家上限估算
INDEPENDENT DESIGN 03

巡回舞台

大招期间允许凌音以受限移速一边蹦跳一边移动，成功触发完美时刻可缩短剩余冷却。大招仍可被打断，保留对手控制与站位反制。

  • 最大体验变化：范围硬控可以追随战场
  • 导师反馈直接转化为克制条件
  • 数值与机制预算分开评估

METHOD

数值不是替代体验，而是给设计建立初始预算。

直给属性直接按单价换算；伤害、治疗、护盾等按命中、目标、覆盖和有效率折算；减冷却先转化为频率收益；控制、位移、吸附和移动施法等难量化效果保留“特效预算”，再用同类卡牌、经验和实测判断。

数值价值 = Σ（子效果满额收益 × 命中／覆盖／次数／有效率修正）
最终判断 = 数值预算 + 难量化机制价值 + 实测反馈

技能占比法和生命周期次数法是两条整局收益估算路径。根据效果形态选假设更少、解释更直接的一条，另一条可用于交叉校验；同一项收益不机械重复叠乘。

CASE 01 · 庇音

护盾与治疗拆开计算

护盾与治疗分别估算，再统一折入平均目标数、战斗内触发次数与有效率，避免把理论满额收益直接当作实战价值。

护盾价值 = 单次护盾 × 平均目标数 × 触发次数 × 有效率
治疗价值 = 单跳治疗 × 跳数 × 触发次数 × 增幅比例数值收益控制在对应品质区间，目标筛选与持续范围另行测试。
CASE 02 · 巡回舞台

剩余冷却转频率收益

先根据完美时刻的预期触发次数估算总剩余冷却缩减，再把它转换成技能释放频率增量，并乘以大招在整局技能价值中的占比。

频率增加 = 总剩余冷却缩减 ÷（1 − 总剩余冷却缩减）
价值 = 频率增加 × 技能占比 × 频率单价移动施法归入机制预算，并通过受限移速与可打断控制风险。
CASE 03 · 音响炸弹

百分比生命伤害先过防御

百分比生命伤害不能按真实伤害直接估值，需要先经过目标防御折算，再乘平均命中目标数和生命周期次数。

伤害价值 = 标称生命伤害 ÷ 防御折算
× 平均目标数 × 生命周期次数 × 伤害单价剩余预算由自动追踪、短暂击飞等难量化机制承担。
CASE 04 · 蓄能

复杂联动先用简化模型

严格模型需要计算常态与热舞状态差值、音量节奏和覆盖率增量，参数链过长。初值先用固定的被动权重概括音量加速收益。

音量加速价值 ≈ 音量获取增幅 × 被动权重 × 频率单价护盾与攻速继续独立计算；后续由实测校正整个卡牌与Build。

表现分档由选取率与选卡胜率综合得到，只用于凌音卡牌内部比较，不是跨英雄绝对评分。理论计算用于控制初始预算，并不代表完整Build已经通过实战强度验证；理论与实战偏移需要后续平衡调整。

09 · CONFIG MECHANISM

落地能力的底层：把技能拆成入口、时间轴与效果结算三层。

要把卡牌方案真正做进游戏，必须理解技能在引擎中的组织方式。以下是从技能配置核对中提炼的通用结构，也是判断“某个效果能不能做、需要改哪一层”的依据。

三层引用链

入口配置（技能基础信息与资源引用）→ 技能时间轴（动画、判定、发射、挂载状态与节奏判定）→ 效果／结算配置（最终状态、伤害与治疗）。制作卡牌的本质，是在这条链上准确增加或调整一个效果，并验证上下游引用。

资源引用

资源类型必须依据正式定义校验。

不同技能、状态、投射物和结算资源拥有各自的标识规则，但不能只靠位数或外观猜测类型。实际工作中需要同时核对资源说明、上下游引用与运行行为，避免复制旧配置时带入错误关联。

伤害承载

发射行为与命中结算分层处理。

生成投射物的时间轴节点只负责发射行为，最终伤害在命中结算层完成。据此可精准定位调整层级：数值问题检查结算配置，弹道手感检查投射行为，前摇与冷却检查技能时间轴。

硬控实现

命中判定与控制状态分开配置。

范围或投射物判定负责确认命中，再向目标施加对应控制状态。效果是持续触发还是一次生效，由受击间隔、最大命中次数与时间轴窗口共同决定。

MECHANISM 01

完美时刻的判定结构

“完美时刻”由窗口判定模块和输入触发模块协同：前者定义节奏点、判定窗口与结果分级，后者在玩家再次点击时发送输入信号。两者解耦，方便复用于不同技能段。

  • 二技能为单次完美判定
  • 大招为多段音浪分别判定
  • 该结构可复用于节奏／QTE类技能
MECHANISM 02

状态检查与条件分支

同一时间轴可以放置多组相似节点，并依据角色是否持有某个状态决定当前生效项。这是实现强化态、完美增伤和卡牌分支的统一思路，也让新增卡牌尽量复用已有逻辑。

  • 强化普攻的结果分支
  • 热舞的强化光环切换
  • 卡牌强化技能的通用做法
MECHANISM 03

状态切换与换普攻

形态切换可通过重定向默认技能槽实现：进入热舞时将普攻切换为增强版本，退出时还原。对于卡牌带来的技能替换，还需要额外检查状态退出、死亡和重置等边界。

  • 热舞：普攻→增强普攻
  • 技能替换需要处理状态恢复
  • 适用于变身与强化形态
10 · DEEP CASE

深度实现案例：为多段大招追加一次表演与判定。

“延时演出”需要在原多段大招后追加一段音浪与完美判定。实现中出现“新增段无法正常触发”，排查后确认并非单一故障，而是三类关联问题依次叠加。问题均已修复，该卡完成本地验证；以下保留排障方法，项目专用字段与标识已抽象化。

问题 01 · 跳转失败

复制技能段时遗漏关联字段。

新增段由复制上一段而来，但其关联资源仍指向旧段。修正新段与对应本体的引用关系后，技能槽才恢复可点击判定。

问题 02 · 提前进 CD

冷却终点仍停留在原末段。

原本的冷却触发节点在旧末段结束时执行，导致新增段尚未点击便进入冷却。将技能结束与冷却时机移动到新的末段后，主流程恢复。

问题 03 · 判定链中断

原末段缺少继续向后传递的条件。

旧末段原本是链条终点，因此没有配置“仍在连续判定中”的检查。新增段后它变成中间段，必须补齐连续状态的传递条件。

根因定位：连续判定状态没有完整传递

通过行为对照和相似技能配置交叉验证，确认多段技能依赖连续状态区分“仍在演奏”与“技能已经结束”。原末段作为终点时无需继续传递；追加新段后，它的角色变为中间段，若仍沿用旧配置，后续流程就会被误判为已经结束并提前进入冷却。

可复用结论

凡“延长技能持续时间／新增技能段”，须同步检查四项：① 相关状态的持续窗口；② 特效节点时长，避免新增段缺少表现；③ 多段连续判定的冷却终点和状态传递；④ 角色动画是否覆盖新增时长。该检查表可复用于其他多段技能扩展。

12 · RETROSPECTIVE

真正的收获，是知道怎样让创意在随机、强度和实现约束下成立。

当前项目仍在制作中。复盘既包括已经形成的方法，也包括尚未完成的验证和应该提前做的工作。

做对的部分

从卡牌列表走向玩法结构。

  • 用共同战斗目标组织Build：不再把“都是辅助增益”当成一条流派。
  • 尊重随机选卡：单卡独立成立，组合后才出现额外循环。
  • 保留克制：移动大招不是无条件加强，而是受限移速且可被打断。
  • 把参考转化为本项目机制：使用派克E、洛R、米利欧W等原型帮助思考，再结合凌音音量、路径、跳跃键和完美时刻重构。
  • 方案进入配置：不是停在文案，已开始处理状态效果、筛选、时间轴和测试问题。
暴露的问题

早期过于保守，也低估了实现约束。

  • V1化学反应不足：增益流是散卡，大招流只是加时长。
  • 过度依赖完美时刻：熟练玩家已能稳定触发，单纯放大奖励既不新鲜也可能失控。
  • 高表现机制缺少预评估：蹦蹦床有记忆点，但没有提前拆程序、动画、目标同步成本。
  • 数值仍含经验假设：部分复杂机制依赖对标和估算，尚未被完整实测验证。
  • 测试覆盖不完整：目前主要验证简单单卡，尚未完成完整Build、极端场景与多人跑测。
如果重做

把可行性与测试设计前置。

  • 在创意阶段建立“表现收益／程序成本／动画成本／反制风险”四维矩阵。
  • 为每条Build画依赖图，明确单卡价值、两卡联动和三卡上限。
  • 虽然不要求Build必成型，仍可模拟局前预选和局内二选一，检查共享卡与品质冲突。
  • 数值表同时记录理论值、实测值、偏差原因和最终调整，避免模型停在纸面。
  • 在配置前建立资源占用、关联组、目标筛选、持续与刷新规则检查表。
后续验证

让作品从“方案完成”走向“闭环完成”。

  • 重做追拍与高频音障。
  • 完成剩余目标效果的配置或可行性确认。
  • 进行单卡、两卡、完整Build和反制场景测试。
  • 若进入线上，跟踪选取率、选卡胜率、Build组合率和不同熟练度分层表现。
  • 用实际数据重构复杂机制的价值计算，而不是只依赖经验估算。
